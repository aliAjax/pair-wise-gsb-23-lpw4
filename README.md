# hxwl-09 半导体洁净室巡检

洁净等级阈值、粒子计数与异常处理看板 —— 两班交接离线补录回网合并。

## 技术栈

React 19 + Vite + TypeScript + CSS，纯前端状态（localStorage 持久化），核心合并逻辑不依赖 React、可独立单测。

## 本地运行

```bash
npm install
npm run dev        # 开发端口 5109
npm test           # vitest：领域规则 20 项 + jsdom 渲染冒烟 1 项
npm run build      # tsc 类型检查 + vite 构建
```

## 交接合并规则（核心）

合并主键：**房间编号 + 巡检日期 + 班次**，同一房间同一班次只有一条记录。

1. **字段级合并**：晚班补录的处理备注与早班的粒子计数分别保留各自来源（班组、批次、编辑时间、阈值版本）；不同字段互不覆盖。
2. **同字段冲突**：同一字段两班都改过且取值不一致 → 该字段停在「待确认」，列出两版及来源，不自动选用；可采用某班版本或输入人工终版，裁决后立即按当前阈值重新做粒子判定。同班组迟到的更旧值不覆盖较新生效值。
3. **异常处理接线**：粒子计数按记录级洁净等级与批次阈值版本自动开单。异常事件链**只追加**：打开 / 处置关闭 / 再次超限重开 / 旧批次忽略 / 阈值复核。
4. **已处置防回退**：已处置异常不会被旧批次改回待处理——编辑时间早于处置时间的超限计数只登记 `ignored-stale` 事件。
5. **新超限重开**：编辑时间晚于处置时间的新批次计数再次超限 → 异常 `reopened`，**原处置备注完整保留**在事件链中。
6. **阈值版本治理**：发布新版本后，按旧阈值做出的判定全部标记 `needsReconfirm`；系统自动按新阈值复核（仍超限的已处置异常自动重开并保留处置），无法判定的保留人工确认入口。
7. **批次台账**：批次幂等接入——已接收批次重放只记 `duplicate` 不二次合并；整批校验失败或模拟写入失败时**整批不落库**进入失败队列，可单独重试（成功后记 `replayed`）。
8. **旧浏览器迁移**：无班次、无阈值版本的旧终端数据，在迁移面板补全后并入同一合并体系；历史处置作为只追加事件保留可查，并按其归属阈值版本参与后续复核。

## 代码结构

```
src/domain/
  types.ts        领域类型（记录/字段版本/异常事件/批次/阈值版本）
  thresholds.ts   阈值版本、粒子计数解析与超限判定
  engine.ts       合并引擎：字段合并、异常状态机、批次台账、阈值升级、迁移
  engine.test.ts  规则单测
  demo.ts         演示批次序列与种子数据
src/state/store.ts  React store（接引擎、动作日志、localStorage）
src/components/     批次控制台 / 记录卡(冲突裁决/异常时间线/复核栏) / 阈值 / 迁移
```

## 演示动线

1. 初始：CR-1201 早班已超限→已处置（更换 FFU、复测 2800）；另有一条 2026-08-20 旧浏览器迁移来的已处置异常；失败队列里有一批可重试。
2. 「接入下一批」依次演示：晚班不同字段各自保留来源 → 迟到旧批次被忽略（不改回待处理）→ 早班新计数 4200 再次超限自动重开（原处置保留）→ 晚班新房间开单 → 早班对计数/备注有异议进入待确认。
3. 可在记录卡上裁决冲突、在失败队列单独重试、重放已接收批次验证去重。
4. 发布 v2 加严阈值：旧判定全部复核，旧机迁移的已处置异常因仍超限自动重开；迁移面板可再补录一条旧数据，历史处置仍挂在异常时间线上。
5. 「重置演示数据」回到种子状态。
