# hxwl-09 半导体洁净室巡检

洁净等级阈值、粒子计数与异常处理看板 —— 交接班离线补录回网合并。

## 技术栈

React + Vite + TypeScript + CSS + Vitest

## 本地运行

```bash
npm install
npm run dev        # http://localhost:5109
npm test           # 领域规则测试（23 个用例）
npm run typecheck
npm run build
```

打开后点 **「载入交接演示」** 可看完整场景。

## 解决的交接班问题

两班在各自离线终端补录**同一房间、同一班次**，回网后不再整条覆盖：

1. **一条记录 + 字段级合并**：记录主键为 `日期#班次#房间`。每个字段（粒子计数、温湿度、
   设备状态、处理备注……）独立带 `fieldRevision` 和来源（批次/终端/操作人/阈值版本）。
   不同字段各自保留来源，夜班的粒子计数不会再被早班整条冲掉。
2. **同字段两班同改 → 待确认**：两批都基于同一旧字段版本改同一字段且值不同时，不静默覆盖，
   在「待确认冲突」面板列出全部版本（含两班终端、操作人、批次、基于版本），班组长点选一版后闭环；
   此后基于新版本的写入会让旧冲突自动收敛。粒子计数冲突期间异常状态机冻结，确认后再联动。
3. **巡检记录与异常处理接起来**：粒子计数按当时阈值版本判定超限即打开异常单；处置只追加
   事件、状态变为已处置。
4. **已处置不被旧批次改回待处理**：按现场封包时间守卫 —— 封包早于处置的旧批次补传，只登记
   复测事实，状态不回退（审计有「守卫拦截」记录）。
5. **新计数再次超限 → 重新打开**：处置之后的新计数仍超限，异常重开，原有处置全部保留在时间线。
6. **阈值版本管理**：每次判定记录阈值版本。版本升级后所有旧判定挂起「重新确认」并给出按新
   阈值的建议（原本合格、新阈值下超限的也会补建档挂起）；人工确认仍超限可重开且保留原处置；
   新版本下新计数到达则自动解除挂起。
7. **批次台账**：按 `batchId` 幂等去重，已接收批次重复回网绝不重复带入；某批写入失败整批回滚、
   只登记 `failed`，批次留在 outbox 可**单独重试**，不影响其他批次；失败重试成功后台账保留
   失败+接收两条轨迹。
8. **旧浏览器数据迁移**：旧数据补上班次与阈值版本后以 `legacy` 批次导入 —— 字段只补空缺不
   覆盖现值，历史处置/判定归档可查，不驱动当前状态机。

## 代码结构

```
src/domain/
  types.ts      领域模型（记录/字段值+来源/冲突/判定/异常事件/批次/台账）
  engine.ts     纯函数合并引擎与异常状态机（无 React 依赖，可单测）
  selectors.ts  看板派生视图
  storage.ts    localStorage 状态与 outbox 持久化
  seed.ts       阈值版本与交接演示批次
  *.test.ts     Vitest 规则用例与端到端场景
src/components/ 冲突面板 / 异常时间线 / 记录明细 / 批次台账 / 封包录入
```

  07:30 厂务在线处置换高效过滤器 → 07:40 终端 C 一批 06:50 封包的旧数据才回网

- B-retry-01：首次写入失败进入待重试队列，可单独重试。

- 阈值升级 v2024-01 → v2026-03：早班 3200（旧限值合格、新限值 3000 超限）挂起重确认。
- B-legacy-01：旧浏览器导出数据补上班次/阈值版本后迁移，2026-08-19 的历史处置仍可查。
